American Magnetics Model 430 programmer for a superconducting magnet **without a
persistent switch**. For a magnet with one, use
[`ami430_persistent`](ami430_persistent.md). There is no setting for this: the driver
you choose says it. The programmer's Load menu must agree (`PSwitch:INSTalled?`). If
the menu says a switch is installed, connecting is refused, and the message names
`ami430_persistent`. The older Model 420 has its own drivers,
[`ami420`](ami420.md) and [`ami420_persistent`](ami420_persistent.md).

**Address.** Over Ethernet: `TCP::<ip address>::7180`, or the RS-232 port. The
programmer's field units (kG or T) and ramp-rate units are read and converted:
`field` is always in T and `ramp_rate` in T/min. The configuration (coil constant,
current limit, ramp rates, quench detection) is set on the front panel, and the
driver only reads it.

## Setting the field

Setting `field` starts the ramp and returns at once, like pressing RAMP on the front
panel. `status` reads `RAMPING`, then `HOLDING`. A sweep that steps the field waits at
every step with a [point action](../../guide/point-actions.md):

```python
wait_until(lambda: get('magnet.status') == 'HOLDING', timeout=3600)
```

A field beyond the programmer's current limit is refused. `pause` stops the ramp.

## Quench

The programmer detects a quench and takes the supply to zero. The driver checks for
one at every call, and the backend checks every `poll_interval` seconds, even when
nothing reads the magnet. A quench:

* aborts a running sweep or script (its data file says why), stops the run queue and
  aborts running user actions;
* is shown by every front end;
* makes field writes refused until it is cleared. Reading still works.

Clear it with `clear_quench` (or RESET QUENCH on the front panel) once the magnet is
safe. See [Robustness](../../guide/robustness.md#safety-faults).
