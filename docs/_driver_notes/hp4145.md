HP 4145A/B semiconductor parameter analyzer, and the HP 4155/4156 in its HP 4145
command set. The protocol follows a 4155 driver verified on the hardware (HP
4155A/4156A HP-IB Command Reference 04155-90120).

The analyzer is put into HP-IB **user mode** (`US`). Every SMU is forced (`DV` / `DI`)
and measured (`TV` / `TI`) point by point, so it works like four source-measure units,
with the same `mode<n>` logic and adaptive compliance as the
[Keithley 2400](keithley2400.md).

* Per SMU 1…4: `voltage<n>`, `current<n>`, `mode<n>`, `Icompliance<n>` /
  `Vcompliance<n>`, `output<n>` and `range<n>`. The 4155/4156 also has a 2 V range.
* Voltage sources `vs1`, `vs2` (±20 V, 1 mV) and voltmeters `vm1`, `vm2`.
* `integration`: short / medium / long.

**Command set (4155 / 4156).** The analyzer must be in its HP 4145 command set.
Option `command_set` tells the driver where it is; nothing is probed:

| `command_set` | the analyzer is in | the driver |
|---|---|---|
| `HP4145` (default) | the HP 4145 command set already (always so for a 4145A/B) | sends no SCPI at all |
| `HP4155` | its own SCPI or FLEX command set | switches it once: `*IDN?`, `CMD?`, `:PAGE` (from FLEX), `:SYST:LANG COMP`, then waits 2 s |

After the switch, the analyzer stays in the HP 4145 command set, also after a
disconnect. The driver then sends no SCPI command (`*IDN?`, `CMD?`, `*CLS`,
`:SYST:ERR?`), because the 4145 command set does not have them. A later
connection in the same backend session does not switch it again. A wrong
`command_set` is an error at connection that says so. Once the analyzer has been
switched, use `HP4145` after a restart of the backend.

**Connecting** sends `BC`, `US`, every source off (`DV1`…`DV4`, `DS1`, `DS2`), `ID`,
`DP1` and `EI1` (4155/4156 only, and not on the earliest 4155A firmware), `IT<n>`,
`BC`.

**Commands and readings.**

* `DV<n>,<range>,<V>,<I comp>` / `DI<n>,<range>,<I>,<V comp>` set and enable SMU
  *n*. `DV<n>` alone disables it. Values are rounded to the resolution of the source
  range.
* `DS<k>,<V>` sets voltage source VS*k*. `DS<k>` alone disables it.
* `BC;TV<n>` / `BC;TI<n>` return one fresh reading, e.g. `NAV+1.2345E+00`. The
  voltmeters are `TV5` / `TV6`. No error queue is polled.

| status | meaning | reading |
|---|---|---|
| `N` | normal | the value |
| `C` / `T` | this / another channel at its compliance | the value |
| `V` | A/D overflow | ±inf |
| `X` | oscillation | NaN |
| `ERROR …` reply | refused | an error |

**Settings.** User mode has no setting queries, so settings are remembered by the
driver. A value written while `output<n>` is OFF is applied when it is switched ON;
this needs a compliance first.

**Output envelope.** The limits are checked before anything is sent:

| source range | max current compliance |  | source current | max voltage compliance |
|---|---|---|---|---|
| 2 V, 20 V | 100 mA | | ≤ 20 mA | 100 V |
| 40 V | 50 mA | | ≤ 50 mA | 40 V |
| 100 V | 20 mA | | > 50 mA | 20 V |

**Outputs on (re)connect.** Connecting and disconnecting switch every source off. A
reconnect, after a failed call or with **Reconnect**, programs again the SMUs and
sources that were on.
