    Scripting and Python¶

    An advanced topic

    You don't need anything on these pages for everyday measurements. The Quick start and the tutorials do everything from the GUI. Come here when you notice that you are clicking the same thing for the tenth time, or the measurement you want can't be described as a grid of points.

    When the GUI is not enough¶

    Some typical cases:

    you want to … use
    run the same sweep at a list of temperatures, fields or gate voltages, one file each a queue script with a loop
    measure first, then decide where to measure next (find a peak, then zoom in) a queue script: run_sweep() returns the data
    put points closer together near something interesting, or walk a path that is not a straight line a custom sweep
    measure while something drifts by itself (a magnet ramp, a warm-up) a time trace: a custom sweep with no swept channel
    check a measurement while it runs, from a Jupyter notebook, or start it from your own program a Python client
    use an instrument easyMeasure has no driver for the Driver Wizard, or write a driver

    How much code?¶

    easyMeasure has code at four levels. Each one is a small step up from the one before.

    1. Formulas. The scale of an alias, the formulas of a composite channel and the mapping of a sweep are single expressions such as (n + 0.15 + D/0.0452) / 1.2. You have used these in the tutorials.
    2. Point actions and user actions. A line or two of Python run at every point of a sweep (if abs(values['Ileak']) > 1e-9: end_sweep()) or at the click of a button (set_many({'Vbg': 0, 'Vtg': 0})). See tutorial 3.
    3. Queue scripts. A whole Python program that the backend runs from the queue, like a sweep. It can set and read channels, wait, and run sweeps one after another. This is the main subject of this chapter: Queue scripts and Custom sweeps.
    4. Python outside easyMeasure. A notebook or program that connects to the running backend: Python clients. And drivers, which are Python classes.

    All of them use the same names: get('Rxx'), set('Vbg', 1.0), and so on. What you learn at one level works at the next.

    A sweep is a dictionary¶

    Everything you set up in the sweep editor is stored as a plain dictionary. Sweep → Save… writes it to a JSON file, and every data file contains it. The Dirac-peak sweep from the Quick start looks like this (examples/graphene_dirac.json):

    {
  "name": "dirac_peak",
  "dimensions": [
    {
      "points": 161,
      "sweep": [
        {
          "channel": "Vbg",
          "start": -8,
          "stop": 8
        }
      ],
      "record": [
        "Rxx",
        "Ileak"
      ],
      "pre_delay": 0.02
    }
  ],
  "post": {
    "constants": [
      {
        "channel": "Vbg",
        "value": 0
      }
    ]
  },
  "metadata": {
    "sample": "BLG-01"
  }
}

    Each box of the editor is a key: points is box 2, sweep box 3, record box 4. A script builds the same dictionary, or loads one saved from the editor and changes a few values. Every key is listed in the sweep definition reference.

    Design in the GUI, repeat with a script

    The easiest way to write a sweep for a script is not to write it at all. Set it up in the editor, check it with Sweep → Validate, save it (Sweep → Save…), and load it in the script with load_sweep(...).
