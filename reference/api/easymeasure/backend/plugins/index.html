    easymeasure.backend.plugins¶

    The plugin manager: finds plugins, runs each on its own thread, and ends them.

    • Where plugins come from. The plugins that come with easyMeasure (easymeasure.plugins.builtin); installed packages that name them under the entry point group easymeasure.plugins (pip install …); <home>/plugins and the folders of the plugin_paths setting: a .py file or a folder with __init__.py each, defining one ~easymeasure.plugins.Plugin subclass.
    • Versions. A plugin declares the plugin API it was written for (API); one this easyMeasure cannot run is not loaded, and the Plugins dialog says why.
    • Its own thread. Everything of a plugin - start, stop, timers, widget callbacks, backend events, the reads and writes of its channels - runs on the plugin's thread. An exception there is logged and shown in the Plugins dialog; the backend goes on. A start that fails leaves the plugin off.
    • Clean disabling, at any time. Disabling revokes the plugin's access to the backend at once, removes its panels, channels and timers and asks the plugin to stop; a plugin that does not return in time (stuck in a loop) is left behind, cut off from everything.
    • The enabled plugins and their options are kept in the backend settings and enabled again when the backend starts.
